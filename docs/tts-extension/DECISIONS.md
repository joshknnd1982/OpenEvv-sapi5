# Decisions

Dated design decisions, newest last. An intentional change to what the engine says is recorded here before it is committed (R8).

## 2026-10-05 (Phase 0)

**D1. Baseline.** Tag `tts-ext-baseline` is commit `10542ae` on `main` (release 1.2.4 plus the licence commits). Work happens on `tts-ext/phase-N` branches. Nothing is pushed unless the human asks.

**D2. Builds that prove the toolchain must not touch tracked files.** The wrapper is built with plain `cmake` into the git-ignored `build_x64`/`build_x86`. Engine modules are built with `engine/build_modules.sh` into `%LOCALAPPDATA%\OpenEvvBuild-ttsext`, a work folder of this project's own, so that the maintainer's release cache (`%LOCALAPPDATA%\OpenEvvBuild`) and the DLLs in `languages/` are left alone. `build_all.bat`, `engine\build_modules.cmd` and `build_all.bat packs` overwrite tracked files and were not run.

**D3. How the checklist counts.** One entry for every representation the chart prints: 175. Where the chart prints the same thing twice (a tone as diacritic and as tone letter, ring above and below, tie bar above and below) each form is an entry, linked by `equivalent_to`, because each is a different input the engine must accept: 163 distinct things. The chart's example ejectives (pʼ tʼ kʼ sʼ) and example diacritic combinations are not entries; the ejective mark is one entry.

**D4. A symbol's stable id is its codepoints** (`U+0288`, or `U+02E9+U+02E5` for a sequence). Codepoints never change; names and numbers have typos and variants across sources.

**D5. What "engine today" means in the checklist.** It is read from code and from the packs' maps only: `already` (one of the seven IBM modules whose phones have an IPA value in `engine/espeak_phonemes.py` has the sound as a phone of its own; frca, jajp and plpl have no such table and were not consulted, so the column can under-report but not over-report), `partly` (said as another phone, reshaped or not; or a mechanism that covers some cases), `absent`, `unknown`. It is a statement of what the engine attempts, not of whether it is right; nothing was measured in Phase 0.

**D6. A correlate stated from memory is tagged `recalled-unverified`** in the research files and the checklist. It is not one of the playbook's provenance tags on purpose: it marks text that must be looked up before any number is taken from it, and any value derived from it enters the master table as `estimated`.

**D7. The official chart PDF is not copied into the repository.** It is CC BY-SA; the project is MIT. It is cited by URL, issue and SHA-256 of the human's copy.

**D8. The research helpers' raw files are kept** (`inventory/research/*.json`, with the brief they were given), because they hold the per-claim sources and the list of what could not be verified. The checklist is generated from them and is never edited by hand.

## 2026-10-05 (Phase 1)

**D9. The harness is `docs/tts-extension/harness/`, Python with numpy and scipy, MIT.** The one exception is `praat_crosscheck.py`, which imports Parselmouth (GPL v3) and is GPL v3 or later by its own header; nothing else imports it (the human chose this: own analyser, Praat as a second opinion). Its Python packages live in a venv outside the repository, `%USERPROFILE%\OpenEvvBuild-ttsext\venv`; not `%LOCALAPPDATA%`, which Windows redirects into the Claude app's private storage when the app creates a folder there.

**D10. One new tool, `src/tools/evv_render.cpp`; no engine or product file changed.** It is `evv_say` for a list of cases, plus two things: it ends its host cleanly (`HostPool::shutdown_all`), and `--annotated` hands a pack's own module text that is already the front-end's output. The cleanly ended host is the whole point: the host lives in a job that kills it when its client exits (`host_client.cpp:53-69`), and a killed host never flushes the frame log (`EVV_KLATT_TAP`), whose tail is then lost (seen on the first try). `CMakeLists.txt` has built an `evv_render` target whenever this file exists since 1.0.0, so no build file changed. The frame, trace and array logs are in the shipped modules already: no logging hook had to be added to the engine.

**D11. Every case is spoken in a host of its own.** An utterance's frames depend on what the instance said before (the same text a second time differs in the voicing of six onset frames and in the noise generator's state). One host per case gives each case the history of the product's first utterance, the same one `evv_say` gives; `evv_render`'s first case is byte-identical to `evv_say`'s (enus and hi). It costs about 0.14 s a case.

**D12. IPA and eSpeak NG phoneme input go through the front-end's `--phonemes` and `evv_render --annotated`.** The host's front-end has no phoneme input. The annotated path gives the product's frames exactly (hi, sw: identical frame logs; ru differs in onset voicing only, from the history), but not its samples: that host warmed up on "Ready. 1 2 3." rather than the front-end's "1 2 3.", so its noise generator is elsewhere. Text input of a pack read by eSpeak NG goes through the host's own front-end, exactly as the product.

**D13. Phones are found two ways, and the markup only where it is proven harmless.** `{A v=1}` switches the accent layer on and changes nothing in enus and the seven template modules (byte-identical sound; checked once per module build by `engine.traces`). The nine other native modules (dede, engb, eses, esus, frfr, frca, itit, jajp, plpl) **do not know the markup and speak it aloud** (dede: 27,852 samples with it, 14,762 without), so it is never given to them; their phones are the array log's runs (one a phoneme plus a silence a sentence), labelled when the input named the phones. Finding for Phase 2: the shipped native modules other than enus were built without the accent layer's text filter.

**D14. The logs are checked and a bad one is spoken again.** About one host in twelve, under load, is ended by the wrapper's 1.5 s grace (`HostPool::stop`) before it flushes. A case is accepted only when the frame log is whole, the frames add up exactly to the warm-up (traced, or calibrated by rendering an empty case) plus the case, and they outlast the sound by 0 to 6 ms plus 2.5 ms a second (measured 1.6 to 3.6 ms on single sentences). Otherwise it is rendered again, up to five times, and then reported as an error.

**D15. Analyser.** Formants by Burg LPC (order 12 at 11025 Hz, 25 ms Gaussian window, pre-emphasis from 50 Hz, as Praat's defaults); F0 by normalised autocorrelation with Boersma's window correction; fricatives by spectral moments above 500 Hz and -10 dB band edges; stops by closure (25 dB below the loudest), burst (a 12 dB rise above 1.5 kHz within the stop's stretch) and voicing onset (a periodic voice bar unbroken into the burst, else F0 found for 20 ms after it: D20, D21); nasals by the deepest valley below its neighbouring peaks. LPC reads a narrow low F1 towards a harmonic (/u/ 378 Hz at F0 110 reads 450; Praat reads 453), so self-tests hold F1 to three quarters of F0, F2 and F3 to 5 %. Praat agrees with the harness on 24 of 24 comparisons (18 engine vowels within 5 %; on the 2 synthetic signals where they disagree the harness is the one nearer the known answer).

**D16. Checks, levels and thresholds** (report.py's docstring is the definition). Check A, engine fidelity: A1 from the frames (every phone the engine meant to sound has a sounding frame) and A2 from the signal (measured F1, F2, F0 of vowels against the frames'), passing at A1 100 % and A2 90 %. Check B: measured values of each golden case's target phone against the reference store, preset 1 against adult male references, passing at 80 % in range; most languages have no reference yet and stay at level 2 for that reason alone. ASR passes at CER 0.15. Levels need every level below them. Failure layers are first-pass labels: `phoneme values` when A or B fails; when only ASR fails, `stress-or-tone` for a pack with tones and `unknown` otherwise (G2P, duration and coarticulation cannot yet be told apart).

**D17. The golden regression keeps metrics, not audio,** for every eSpeak NG phoneme each pack maps (said by name in ['aCa] or [t'Vta]) and every phone each native module declares (`[.1aXa]), with the frames' and the sound's hashes. Identical frames and sound pass at once (D20); otherwise any requested value that moves beyond 0.5 % or 1 unit, any measured one beyond 2 %/15 Hz, 1 dB or 3 ms, a phone sequence that changes, or a case missing or new, fails. Module phones whose names hold `:` or `~` cannot be written in an annotation and are reached through words (golden.py `TEXT_CASES`).

**D18. ASR is Whisper large-v3 through faster-whisper on the GPU** (float16; CTranslate2 has no INT8 on compute capability 12.0), language given, beam 5, temperature 0. Its sentences are Common Voice's sentence text (CC0) and, where it has none, Tatoeba's (CC BY 2.0 FR, each sentence's id and author kept). FLORES+ (CC BY-SA), UDHR (no licence stated) and Wikipedia (CC BY-SA) are not used. A language without a Whisper code or sentences is "ASR unavailable", never scored.

**D19. The reference store takes ranges only from what a source gave** (mean ± 2 SD, quartiles ± 1.5 IQR, geometric mean ×/÷ ratio², or min..max), matches a pack's own variety or language only, and records the research helper's doubts in each entry. Its 956 values come from 14 sources the helper opened; 120 Peterson & Barney means and SDs are `derived` (computed by the helper from the data file).

**D20. What the independent review of Phase 1 changed** (R15; a fresh-context helper read the diff against the exit criteria). Fixed:
- *VOT*: voicing carried over from a preceding vowel into a closure was read as prevoicing (Hindi /p t k/ stored -117 to -49 ms). Prevoicing is now a voice bar running unbroken into the burst; a self-test case with carried-over voicing was added. Hindi now reads /t/ 20 ms, /k/ 12, /tʰ/ 70, /b/ -81 (its map asks 15, 18, 67 and lead 85).
- *Check B ignored every consonant reference*: the VOT, fricative and nasal sources pool both sexes (`mixed`) and lookups wanted the voice's own group. A pooled entry is now used where no group entry exists. VOT and fricative means still give no range (no spread is published in the sources read), so of the consonants only the general nasal ranges are checked, and the tone entries wait for Phase 4's tone cases; the docs say so instead of implying more.
- *The golden could not see a change inside the synthesiser*: the frames are logged before it runs. A case now passes at once only when its frames **and** its sound are identical; otherwise its measured values are compared.
- *The golden skipped phonemes a pack borrows from another table* (ru `@en:A:` for English words): they are now said after eSpeak NG's table switch (`[[_^_en ...]]`, which gives exactly the map's sound), 2,776 more cases. What cannot be said is listed per pack as `not_covered` with the reason (15 entries: the module phones named with `:` or `~`).
- *Check A did not compare what sounded with what was asked*: A0 does now. Every one of the 642 traced phones that differ from the phone meant is a piece of it (the module sounds its affricates as stop + fricative), so none counts as a substitution; any other would fail A. Cases whose phoneme the map gives no phone of its own (an /h/ heard only as aspiration) are counted per language beside check A.
- The spectrograms now carry the reference bands where a native pack's vowel has one; the analyser's docstring no longer claims a METRICS table; one language's render failure no longer loses the ASR run; four handoff paths in PROJECT_STATE.md had lost their backslashes to escape codes.
Not changed: the failure layers `G2P` and `duration-or-coarticulation` are not assigned yet (D16 says why); that is Phase 6's triage.

**D21. What the re-review changed** (R15 allows one). The VOT fix of D20 was incomplete: when the burst detector found a burst in the next vowel, that vowel was read as prevoicing (175 of 1,061 voiceless-stop cases negative, engb /k/ -55 ms). A burst must now lie within the stop's own stretch, and otherwise none is reported. Checking what was left (144 of 909 voiceless-stop cases still negative, nearly all in the dedx and itix templates) against the frames showed one more fault: a weak release stays under the overall "quiet" line for a few milliseconds, so the burst was found about 13 ms late and the frication's own low-frequency energy passed for a voice bar. The burst is now the high-frequency jump alone (within 40 dB of the loudest), and a voice bar counts as prevoicing only if it is periodic. The bursts then fall where the frames release (ba /k/ 155 ms, frames 155; bn /p/ 184, frames 185). A0 now accepts as pieces only an affricate's stop or fricative, not any part of a phone's IPA. The docs had still claimed that the fricative references are checked; they cannot be (means only).

## 2026-10-05 (Phase 2: the design)

These are the decisions of `DESIGN.md`. **The human approved the design on 2026-10-05** (D35).

**D22. Extend the engine; do not rewrite it.** The synthesiser core (`openevv/src/klatt`) is kept exactly as it is. An independent rewrite cannot give today's samples (about 1,490 lines of integer signal code with fifteen behaviours no textbook describes, two tables with no known formula, a gate that compares SHA-256 of samples), and what it would buy either fits behind a switch in the present one or is not needed for the chart. The modules' rules are kept too: 183,000 to 393,000 lines a module, and Phase 1 shows they work very well where they fit. New ability goes into the accent layer and the front-end, which are ours. No core synthesis component is proposed for replacement. `DESIGN.md` 12.

**D23. One master table of sounds, in engine-neutral units, in files of our own.** `ipa/table/*.toml`, MIT. Hertz for one reference speaker (an adult man), milliseconds, and decibels against the peak of an open vowel in the same voice. Every number carries a provenance tag; `literature` needs a source that was opened. What this engine needs to hit a target (`trim`) is kept apart from what the sound is. Nothing is copied from eSpeak NG or from ShareAlike sources. `DESIGN.md` 3.

**D24. The engine still receives ratios.** The adapter turns hertz into ratios against what the carrier phone measures in the module. Head size multiplies F1 to F5 by one factor and touches nothing else (measured: 1.25 at 0, 0.75 at 100), so a ratio is exact for every head size and no voice setting has to reach the accent layer. For the female and child presets it is approximate, and that is stated. `DESIGN.md` 3.3, 7.

**D25. Sounds are composed, in two places, from one source.** A modifier is a feature edit plus a transform of four operations (scale, move part of the way to a target, add, set or insert), applied in a fixed order. The adapter composes exactly when a pack is built; the front-end composes when speaking, by merging lines the adapter wrote. Lookup order: exact, composed, nearest by features. Every fallback writes a warning; in the harness, the pack build and the tests a warning is a failure. `DESIGN.md` 2.

**D26. The features follow the chart**, not a binary system: place on a scale, stricture, nasal, lateral, sibilant, airstream, voicing, aspiration, release, secondary articulations; height, backness, rounding for vowels. So each chart letter has one bundle and each chart mark is one edit, and a machine can check both. `DESIGN.md` 2.1.

**D27. Every one of the 175 checklist entries is decided** in `design/TRACEABILITY.md`, written by `design/build_traceability.py`, which refuses to write it with an entry undecided, a capability that serves no symbol, or equivalent entries decided differently: 109 as-is, 50 composition, 16 new mechanism; meant to end 67 mapped, 53 composed, 55 created. The end state of a letter is a rule, applied by the builder from the checklist: `mapped` if one of the seven IBM modules the checklist read has the sound as a phone of its own (D5: frca, jajp and plpl were not consulted, so the created letters can only become fewer), `created` if none has (the sound is then designed here under the USP and registered, whether it needs a new mechanism or only the present keys), `composed` for a base plus a general rule. These are plans; every entry is still `MISSING`.

**D28. Twelve capabilities, in order.** Foundations for every symbol: C1 never silent, C2 the IPA reader, C3 the master table with its validator and adapter, C4 composition when speaking. Then C5 pitch (register steps, a slope per phrase, a consonant's push on pitch under a **new** key), C6 phonation, C7 syllabicity, C10 timed events on a carrier phone, C11 trills at a stated rate. Two defects are fixed first and are not capabilities (D33). Three are built only if a written measurement fails without them: C8 edge transforms, C9 the nasal and second pole/zero pair set directly, C12 transient excitation. `DESIGN.md` 4.3.

**D29. One reference template carries the proofs.** Every Tier A symbol is proved on one template module; the same tests run on the other six and are recorded, without blocking the checklist. Which template is chosen by measurement at the start of Phase 3 (each of a few well-recognised languages built for all seven); if unclear, the German-based one.

**D30. Corrections to earlier documents, found in Phase 2.**
- D17 and the harness README said module phones named with `:` or `~` cannot be written in an annotation. They can, in single quotes: measured on dede, `` `[.1a'E:'a] `` 9,482 samples against 62,051 unquoted (spelled as text); `` `[.1t'a~'t] `` 9,339 against 59,609. The 15 `not_covered` golden entries can be covered in Phase 3.
- D13 said nine native modules do not know the accent markup. It is nine and also the 32-bit US English module: the strings `EVV_ACCENT_TRACE` and `{A v=1` are in 15 of the 34 module DLLs (64-bit enus and both builds of the seven templates). The cause is the age of the files, not a build setting: they were committed before the accent layer and never rebuilt.
- `ARCHITECTURE_MAP.md` 9 says at most 4 phones a map entry. A map entry may hold 8; 4 is the limit of a `says` rule.
- `ARCHITECTURE_MAP.md` 6 calls `df1` dead. The synthesiser ignores it, but the rules do write it (always 0 in what was measured); `db1` and the ten `a*v` words are the ones nothing writes.
- `docs/SOUNDS.md` lists the sound key `f0`. It has no effect in any shipped pack: it works only without the layer's own pitch, and all 145 packs use that.

**D31. What must not change** (`DESIGN.md` 12.2): the two COM class ids; the registry path of the voice list; token ids, voice names and attributes; existing tags, names and locale numbers; eight presets a pack; the settings file and data folders; the pack folder layout and `language.ini` keys, with `phonemes.map` kept; the pipe protocol (version 1, message and item numbers, structure layouts) and the front-end protocol; the installer's identity and upgrade behaviour; and the sound of every existing language. Every change of behaviour in the front-end or the accent layer is tied to a version line in the map; a map without it is read and spoken exactly as today. The one exception is the fix of a listed defect (D33), which applies to every pack and is shown, approved and recorded like any intended change.

**D32. Verification rules added to D16.** A new check A3 asks whether what was meant voiceless or silent stayed so (the pack's sound definitions may add no voiced frame to a voiceless phone or a pause), and the golden regression gains each consonant at the end of a word and in a cluster. A contrast test (different from the nearest neighbour, in the right direction) and a specification test (for created sounds) are added, but neither gives level 3: "verified" stays reserved for values inside cited ranges. Every spectral reference is evaluated from 0 to 5.5 kHz, because with its default resampler the engine produces nothing above 5512 Hz and it can never place a formant above 5000 Hz. A symbol's state (`mapped`, `composed`, `created`) needs a rendered, measured proof and is separate from its level. Migration is by stages M0 to M6, each proved by byte-identical maps or by the golden. `DESIGN.md` 10, 11.

**D33. What the independent review of Phase 2 changed** (R15; a fresh-context helper read the diff against the phase's exit criteria and checked the facts in the code).
- *A defect in the released product, found by the reviewer and measured again.* The design had said that a stop before a pause gets none of its release keys. The opposite is true, and worse: after a stop whose sound has a voice-onset key (`vot`), the accent layer switches voicing on and holds it until the module's next voiced frame, whether or not what follows is voiced (`evv_accent.c:2110-2120`). Measured on the shipped modules: Russian "кто.", the t voiced in 15 of 21 frames (Romanian "pta.", no such key: 0 of 11); Russian "псы.", the s voiced in 25 of 27 (Romanian "taxa.": 0 of 18); Hindi "आप.", the final pause voiced in 92 of 92 frames at about 7 dB under the loudest part of the word (Hindi "आपा.": 12 of 92, the vowel dying away; Romanian "pot.": 0 of 90). The breathy-release key (`brth`) does the same for the length of the breathy release (`evv_accent.c:2142-2155`): Hindi "दूधसा.", the s voiced in 17 of 20 frames with friction left in 3 (plain d: 0 voiced, friction in 20); Hindi "दूध.", the final pause voiced in 17 of 83 frames (plain d: 0). The consonant also loses its own noise: Russian "псы.", friction in 4 of 27 frames of the s (Romanian: 18 of 18). All 145 packs have such sounds: 930 definitions with `vot`, 542 of them in the 87 packs on the German-based template, and 196 with `brth`. Plain p, t and k all carry `vot` in 61 of those 87 packs, in both packs on the American English template and in one on the British one; elsewhere only marked stops do. The ten native languages are not affected. **Not fixed in Phase 2** (the phase builds nothing; a fix changes what 145 languages say and ships only in rebuilt template modules). It is defect X-1 of `DESIGN.md` 4.4, to be fixed first, as an intended change shown to the human; `OPEN_QUESTIONS.md` Q11 asks whether it should also go out at once.
- *The migration plan had no place for rebuilding the template modules*, although the accent layer is compiled into them and no engine change can ship otherwise, and although modules built from source have never been compared with the shipped ones. Added: a baseline (the seven templates rebuilt from unchanged source must give an identical golden) before the first change; development in a staging folder that the product reads before `languages/`; files in `languages/` replaced only at stated points with the human's say-so. Question 4 was widened to ask for exactly that. `DESIGN.md` 11.2.
- *`mapped` and `created` had no rule* (ʙ created but ʀ mapped; ʜ created but ħ mapped). Now a rule the builder applies from the checklist (D27). The counts changed from 113 / 53 / 9 to 67 / 53 / 55.
- Smaller: the ejective row lacked the made silence and the hold it uses after an affricate, and the lists of symbols under C5 and C6 did not match the table; the feature table had no place for apical and laminal or for the partial shifts; C8, C9 and C12 had a trigger but no test; the pack example had empty sections and no way to drop one inherited override; "at most 40 ms" for a tap had no source and was removed, and the trill range now names its source; "nothing above 5512 Hz at any output rate" was true only as the product is set up; the German-based template's "50 phones" is about 50 (49 measured).
- Not changed: the reviewer found no row of the traceability table whose described realisation was phonetically wrong, and confirmed in the code every other fact it sampled.
- Second defect listed on the way (X-2): the tone key `av` is read and never applied.

*What the one re-review changed* (R15 allows one). The defect had been described too narrowly: the first write-up named only the `vot` key and said that the plain stops of all 87 German-template packs carry it; the re-review found the `brth` key doing the same and counted 61 of 87 (both measured again and now in the text above and in the fix X-1). It also found: the two lists of what must not change lacked the defect exception (added to D31 and `DESIGN.md` 12.2); the end-state rule said "no IBM module" where the checklist read seven of the ten (reworded, D27); "nothing above 5512 Hz" holds only with the default resampler, and `Resampler=none` is an ordinary user setting (reworded); the key `before` had two meanings in a pack's rule (now `when_before` for the context and `place_before` for the position); the module-files plan did not say which modules the committed golden describes while changes are staged (now: the committed golden is always of `languages/`, the staged modules have their own, and both are replaced in one commit); the trill range was cited as that paper's finding when the paper calls it the canonical range and its own medians are 23 to 28 Hz (reworded; a second source in Phase 4). No further review is made (R15).

## Phase 3 (2026-10-05, branch `tts-ext/phase-3`)

**D36. Where Phase 3 builds and stages, and a build defect found on the way.** Template modules are built outside the repository in `%USERPROFILE%\OpenEvvBuild-ttsext\build3a\openevv` (a copy of `openevv/`; `%LOCALAPPDATA%` is redirected by the Claude app, so it is not used) and staged with `harness/stage.py` in `%USERPROFILE%\OpenEvvBuild-ttsext\stage-base` (the seven rebuilt from unchanged source) and `...\stage` (with the defect fixes). `languages/` is not touched (`DESIGN.md` 11.2). **Defect found:** building only the template modules in a fresh folder fails for `itix` and `esex` (`notation.py`: "it_phone.obj names fence_03, and lang/itix/rules/symbols does not say where that is"). `tools/module/clone.py` copies `lang/<parent>/rules/constants.letters`, which only a build of the parent writes (`tools/rules/letters.py write <parent>`, run by the parent's rulecode step); the shipped modules were built after their parents in one folder, so they had it. Worked around by running `letters.py write` for every parent that has a `letters` file (`eses`, `enus`; and `itit` for `itix`) in the work copy, then building the templates with `engine/build_modules.sh`'s own loop without its refresh of the copy (`build_in_place.sh`, in the scratch folder, so that a source edit in the repository could not leak into the baseline). Not fixed in the tree: `OPEN_QUESTIONS.md` Q12.

**D37. The engine's own gate runs here.** `openevv/test/matrix.sh` runs under MSYS2 with the Windows probe: `make win-probe LANGS=lang/enus RULES=c` (266 s) then `EVV_MATRIX_NATIVE=build/probe.exe bash test/matrix.sh check enus`: "enus: 98 cases, all as they were", exit 0, 109 s, on unchanged source. So by `DESIGN.md` 10.4 it is required for every change under `openevv/src`. Only the Windows probe (`probe.exe`, 64-bit) with `RULES=c` was tried. Upstream asks for six builds (`probe`, `probe32`, `probe.exe`, each with `RULES=c` and `RULES=bytecode`; `openevv/CLAUDE.md`); `probe` and `probe32` are made upstream inside `nix develop`, and whether they can be built under MSYS2 was not tried. Every result says which builds ran.

**D38.
